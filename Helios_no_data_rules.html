How Helios charts handle missing data

Some KPIs have periods with nothing to measure. IA Response On-Time in October is one: no responses were due yet, so it is 0 out of 0. Today that shows as 0.0%, "down 100%" and Critical, which is wrong.

The fix is to treat every period as one of three states, never two:

Has data49 of 80. Drawn, and judged against limits.
A real zero0 of 5. Drawn at 0, and can be Critical.
No data0 of 0. Not drawn, and never judged.

1Empty, not zero

A period with nothing to measure has no score at all. It must stay empty so it can't be mistaken for a real 0% and turn Critical.

Today

0 of 0 is drawn as 0%. The line dives and turns red.

With the rule

Nothing to measure, so no point. The line stops at July.

Data engineerWhen the bottom number is 0 or there are no records, store null, not 0. Never fill missing values with 0. Keep the top and bottom numbers as separate columns.
Back endReturn null for that period's value, never 0 by default. Send the top and bottom numbers with it.
Front endTreat null as "no data". Never turn it into 0 by accident: check every place that adds a default value or converts to a number.

2The chart runs to today

The chart always shows the full time range up to now, so people can see a period is missing rather than wonder where it went. The line just doesn't pass through empty periods.

Today

Reg / Customer Audit: the axis ends at July. Is the rest missing, or just not shown?

With the rule

The axis runs to today and the gap is labelled. July's 0 of 5 is a real zero, so it stays.

Data engineerNothing for this rule.
Back endReturn every period up to today for the selected D, W, M, Q or Y, with null for the empty ones.
Front endRun the axis to today. Break the line at empty periods. Show a light grey "No data" label, and a tooltip saying "No data for Oct 2026".

3Headline from the last completed period with data

The big number and status at the top come from the most recent finished period that has data, and say which one. A half-finished or empty period never decides whether a KPI is Critical.

Today

The headline reads the half-finished, empty quarter.

With the rule

The headline uses July, the last finished quarter with data, and says so.

Data engineerNothing for this rule.
Back endReturn the latest completed period with data: its value, its label, its status, and the change against the previous period that also has data.
Front endShow the value with "as of Jul 2026", and the status from that period.

4Stale data gets its own warning

If data stops arriving, the KPI says so plainly instead of quietly showing an old status. That tells you it's a data problem, not a performance problem.

Today

Data stopped after April, but the status still says Critical as if it were current.

With the rule

Grey, not red. It reads as a data problem to chase.

Data engineerProvide the latest data date for each KPI.
Back endFlag a KPI as stale when its latest data is more than one full period old at that KPI's frequency, and return the "since" date.
Front endReplace the status with a grey "Data not updated since Apr 2026".

5Missing data never lowers a score

Only KPIs with real data count towards a section's score or a person's percentage, so nobody is marked down for a period with nothing to measure.

Today

Empty cells counted as 0 drag the score down. The section looks like it is failing.

With the rule

Empty cells show "–" and are left out. The score reflects only real data.

Data engineerIf section scores or person percentages are calculated in the gold tables, leave out KPIs with no data rather than counting them as 0.
Back endSame rule if scores are calculated in the backend. Return empty heatmap cells as null.
Front endShow empty cells as a grey "–" with a "No data" tooltip.
Rule 5 sits with whichever of the data engineer or the back end calculates the scores today. Chart values are rounded from the IA Response On-Time quarterly view; rule 2 uses the Reg / Customer Audit chart.
